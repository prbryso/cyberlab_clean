# iSecurity Design Language

## Every lesson begins with a problem.

Never begin with a definition.

Never begin with a paragraph.

Begin with a situation.

--------------------------------

## The learner always makes a decision first.

Think.

Then learn.

Never the reverse.

--------------------------------

## Every lesson has a visual model.

The learner should SEE the system.

Not simply read about it.

--------------------------------

## Every defense follows naturally.

Do not say:

Use MFA.

Instead explain WHY MFA changes the attack.

--------------------------------

## Every screen answers ONE question.

Avoid information overload.

One concept.

One screen.

--------------------------------

## Minimize text.

If a picture can replace 100 words,

use the picture.

--------------------------------

## Every lesson is a conversation.

Ask questions.

Challenge assumptions.

Reveal the answer.

--------------------------------

## Reward curiosity.

Never punish mistakes.

Wrong answers become learning opportunities.

--------------------------------

## Make invisible systems visible.

Networks.

Authentication.

Encryption.

Operating systems.

Memory.

Protocols.

Attack chains.

Show them.

--------------------------------

## Every lesson ends with confidence.

The learner should think:

"I understand why."

Not

"I memorized another rule."
