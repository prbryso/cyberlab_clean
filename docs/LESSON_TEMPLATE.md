# iSecurity Lesson Template

## Educational Philosophy

Every lesson must teach the learner how the system works—not simply what rule to follow.

The objective is to develop intuition.

When learners understand the system, they can respond correctly to situations they have never seen before.

The learner should constantly be asking:

• What is happening?
• Why is it happening?
• How is the attacker thinking?
• How does the defense change the outcome?

Every lesson should answer those questions.

---

# Standard Lesson Structure

## 1. Mission

State the objective.

Example:

MISSION

Prevent an attacker from taking over user accounts.

The learner immediately knows what success looks like.

---

## 2. Scenario

Present a realistic situation.

Never begin with definitions.

Example:

An attacker has obtained 250 million usernames and passwords from a recent data breach.

You are the attacker.

What do you do first?

---

## 3. Learner Decision

Force the learner to think before teaching.

Example:

Which accounts would you attack?

○ Banks

○ Gmail

○ Corporate VPN

○ Social Media

There should almost always be a decision before an explanation.

---

## 4. Reveal

Explain the consequences of the learner's decision.

Do not simply say "Correct."

Explain WHY.

Teach the attacker's reasoning.

---

## 5. System Model

Show how the system actually works.

Examples:

Credential Stuffing

Password Reuse

Authentication

Hashing

Network Routing

Email Delivery

Operating System Memory

This is where diagrams become extremely valuable.

The learner should understand the entire system.

---

## 6. Attack Path

Show how the attacker exploits the system.

Inputs

↓

Weakness

↓

Exploit

↓

Impact

---

## 7. Defense

Show how changing the system changes the outcome.

Examples:

Unique Passwords

MFA

Network Segmentation

Least Privilege

Input Validation

Patch Management

The defense should make sense because the learner now understands the system.

---

## 8. Interactive Exercise

Every lesson should include at least one interaction.

Examples:

Choose an attack

Drag-and-drop

Simulation

Animation

Packet tracing

Password cracking demo

Header analysis

Traffic visualization

The learner should DO something.

---

## 9. Knowledge Check

Short.

Conceptual.

Not trivia.

Good question:

Why does credential stuffing succeed?

Poor question:

How many characters should a password contain?

---

## 10. Summary

Three to five key ideas.

Not rules.

Concepts.

---

# Design Principles

Teach systems.

Teach attacker thinking.

Teach cause and effect.

Teach decision making.

Avoid memorization.

Avoid long paragraphs.

Prefer interaction over reading.

Prefer diagrams over text.

Prefer reasoning over rules.

Every screen should answer:

Why?

Not simply:

What?

---

# The iSecurity Standard

A learner who completes a lesson should be able to explain:

How the system works.

How the attacker exploits it.

Why the defense works.

How to recognize similar attacks in the future.

If the learner can only repeat a rule, the lesson is incomplete.
